# 缓存与同步

[English](../en/Synchronization.md)

Termgram 会先显示本地缓存的聊天列表，再连接 Telegram。打开已有缓存的聊天时，
先读取最近一页本地消息，同时在后台获取最新内容。同步期间仍可阅读缓存。
发送消息等服务端操作会等待登录完成。

拉取历史、刷新聊天列表等请求不会阻塞实时消息。对于正在查看的群聊，还会按照
Telegram 返回的间隔主动补取差异。离开聊天或终端失去焦点后，会停止这项主动轮询；
普通推送和差异恢复继续运行。

每个会话文件旁都有独立的 `*.cache.sqlite3` 数据库，保存消息正文、聊天元数据和
已下载附件的路径。登录凭据和用户设置分别保存。Unix 系统下数据库文件只允许当前
用户访问；数据库本身不加密。

缓存只包含 Termgram 已收到或加载过的消息，不代表账号的完整历史。每个账号最多
保留 100,000 条消息记录，旧记录会被清理。如果 Telegram 已无法重放某段过旧的差异，
对应的缓存会失效，并在查看时重新拉取。

清理缓存时，先退出 Termgram，再删除对应会话的 `.cache.sqlite3` 文件。保留
`.session`、`settings.conf` 和 `appearance.json` 即可保留登录状态与偏好。媒体文件可
单独删除对应的 `.media` 目录。同一账号缓存同时只允许一个进程持有。下次启动会重新建立消息缓存。

完整更新批次及其同步进度按顺序提交。写入中断后可能重放已收到的更新，但不会用
超前的进度跳过尚未提交的消息。Telegram 会话中的 peer 元数据与消息缓存进度分开管理。

底层 Grammers 更新引擎遵循 [Telegram 更新协议](https://core.telegram.org/api/updates)。
目前尚未进行与 Telegram Desktop 的端到端延迟对比测试。
